# WORK HACK LIBRARY

AI API・外部データベース・有料サーバーを使わない、静的PWAの知識書庫スターターです。

## 含まれる機能

- 6カテゴリーの知識書庫、検索、カテゴリー・未読フィルター
- 未読／読みかけ／読了、お気に入り、あとで読む
- 記事ごとの個人メモ
- 出典・根拠種別・信頼度・最終確認日表示
- 海外記事用の原文情報フィールド（記事データに `origin: "overseas"`、`originalTitle` などを追加）
- 記事ごとのミニクイズ、全記事クイズ
- タグによる関連知識マップ
- JSONバックアップ・復元
- ダークモード、文字サイズ変更
- Service Workerによるオフラインキャッシュ
- GitHub Actionsで毎日03:00 JSTを目標に検証・再デプロイ

## GitHub Pagesへの公開

1. GitHubで新しいリポジトリを作成します。
2. このフォルダの中身をリポジトリの `main` ブランチ直下にアップロードします。
3. リポジトリの **Settings → Pages → Build and deployment → Source** を `GitHub Actions` にします。
4. **Actions** タブでワークフローが成功したことを確認します。
5. `https://ユーザー名.github.io/リポジトリ名/` で開きます。
6. スマホのブラウザメニューから「ホーム画面に追加」するとPWAとして利用できます。

公開URLはリポジトリ名やアカウント名に応じて変わります。

## 毎朝3時の自動処理

`.github/workflows/pages.yml` のcronは `0 18 * * *` です。GitHub ActionsはUTC基準のため、日本時間の午前3時を狙っています。GitHubのスケジュール実行は混雑等で遅延する場合があり、3時ちょうどを保証しません。

現状の定期処理は「記事データの検査とサイトの再デプロイ」です。AIで記事を自動生成したり、外部サイトを自動翻訳したりはしません。新しい記事は編集・出典確認後に `data/articles.json` へ追加し、pushすると公開されます。

## 記事の追加

`data/articles.json` に既存記事と同じ形式のオブジェクトを追加します。`id` は重複しない値にしてください。最低限、タイトル・カテゴリー・要約・本文・出典URL・最終確認日を入力してください。海外情報の場合は `origin: "overseas"` と `originalTitle` を追加できます。

記事は公開リポジトリに含まれるため、著作権で保護された記事本文や許諾のない画像をコピーしないでください。原文リンクと独自の要約・解説を中心にし、画像のライセンスも記録してください。

## 個人データと注意点

読了状態・お気に入り・メモ・クイズ結果はブラウザの `localStorage` に保存され、GitHubには送信されません。端末間同期はありません。設定画面からJSONバックアップを定期的に取得してください。ブラウザデータを削除するとバックアップしていない個人データは失われます。

記事データ・アプリコード・画像は公開リポジトリから誰でも閲覧できる前提です。個人情報や秘密情報を記事データに入れないでください。

## 現状のプロトタイプに関する注意

- 初期記事は機能確認用のサンプルです。`status: "review"` の記事は、出典・記述を確認してから公開用にしてください。
- `verified` は公式資料等の確認を行った記事にのみ設定してください。
- 「信頼度」は編集上の目安であり、正式な科学的エビデンス評価尺度ではありません。
- クイズ結果は簡易記録です。高度な復習スケジューリングや端末間同期は未実装です。
- 海外情報の翻訳・要約は手動で編集・確認する運用です。
- 記事の画像欄は `image` にリポジトリ内の相対パスを指定します。画像はWebP等に圧縮してください。

## ローカルで確認

Pythonがあれば、このフォルダで次を実行します。

```bash
python3 -m http.server 8000
```

ブラウザで `http://localhost:8000` を開きます。`file://` 直開きでは記事JSONの読み込みやPWA機能が動作しません。
